# Model Recovery Surface — Phase 6 Execution Plan

This tape implements `contracts/FACE_TABLE_V1.md`, `contracts/THREE_PLANE_DIFF_V1.md`,
`contracts/LORE_RECOVERY_UI_V1.md`, and `contracts/SCENE3D_RECOVERY_ABI_V1.md`.
Authored faces are primary rows. Phase 1 is the native/host/Seat face table. The visual
surface starts only after the headless table passes. All fixtures are generated in memory or
under a temporary directory; no game 3D model enters a commit.

For every numbered step, follow `.agents/skills/refactor-plan/references/execution_rules.md`:
append the result to `state/completed.txt`, leave `state/current_step.txt` at the last
completed number, and write failures to `state/blocked.txt` without improvising around them.
Each section-close commit stages only the paths named by that section. Workers do not push.

## Dependency order and parallel lanes

```text
A baseline
  → B native face facts → C operation predicates → D host + Seat (first deliverable)
                                          → E saved/resident/preview diff
                                          → F Scene3D recovery capture ABI
                                          → G Lore immutable history + retention
                                          → H typed client + status cache
D + E + G + H → I visible Blob Explorer and Recovery control
F + G + I → J undoable restore/guarded mutations
all sections → K severance and acceptance
```

Sections A–K execute in numeric order. D establishes face/preview session doors; F later
extends that ABI once for recovery capture. This deliberately avoids concurrent edits to
`abi.zig`, Scene3D module/runtime ownership, AppFrame, Inspector, or shared Seat tests.
