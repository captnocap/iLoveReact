Studio.tsx → studio/

A side-by-side rebuild of the Studio modeling viewport. Two co-equal tracks: decompose the 3,915-line file, and re-architect the UI so it stops cramming, fighting itself, and blocking expansion. Logic stays bit-for-bit identical; the chrome gets rebuilt. One-line swap in, one-line revert.

Two monoliths, not one. The obvious problem is a 3,915-line file whose interior is a single 2,680-line component. The other problem — just as important — is that everything that component renders is jammed into one rectangle with no layout system: ~13 overlay layers, 46 controls, and exactly one z-index in a thousand lines of JSX. They stack by accident of mount order, so panels overlap and some controls literally can't be reached. Porting the UI verbatim would freeze that in place — a net loss. So the decomposition's presentational step doesn't lift toolbars as absolute boxes; it introduces a real chrome shell with named dock zones, an icon-first control vocabulary, and self-serve, rebindable hotkeys. The current Studio.tsx is never touched — it stays frozen as the diff breadcrumb.

3 · Principles

Lift logic, rebuild layout

Handlers, state, hooks, and what each control does move verbatim — same results, same keys. What gets redrawn is only where things sit. Behavior parity is hard; layout is intentionally new.

Dock, don't float

Every toolbar/overlay becomes "I live in zone X" instead of "absolute at these coords." A chrome shell owns the zones and the stacking, so nothing lands on top of anything by accident.

State in hooks, JSX dumb

Each tangle of state becomes one hook (useStudioCamera…). Panels are presentational and take props. The hooks own the how; panels own the look.

Icons over text

Adopt the existing <Icon> primitive (@reactjit/icons/Icon, already used by the layer strip). A glyph + tooltip costs a fraction of the width of a worded button — that reclaimed space is the whole point.

Self-serve, never ask

Hotkeys and toggles live in settings, editable by you. Don't like a binding? Rebind it in the panel — no code change, no request. Defaults preserve today's behavior.

Content first, verbs earn pixels

A layer's name, a part's size — the thing — gets the room. Actions reveal on hover/active, collapse behind an overflow, or move to drag. Density is opt-in, not the default.

Labels name, they don't narrate

Chrome shows state and identity — never instructions or restatements. "drag off model = orbit", "scroll = orbit", "toggle on!", a "mesh editor" chip beside an "OUTLINER" title: this flavor text occupies permanent pixels to say what a tooltip, the KeyLegend, or an empty-state should say on demand. Cut it; it adds up.

4 · The UI architecture UI

4.1 — A chrome shell with named zones + a z-scale

One layout primitive, StudioChrome, owns the viewport's edges as dock zones. A panel says which zone it belongs to; the shell handles placement, overflow (scroll/collapse), and stacking. Z-index stops being ad-hoc — it's a fixed token scale, so "is this on top?" has one answer.

Dock zones

  • topBar — global tools (modes, transform, file/texture/compile)
  • contextRail — the per-mode edit ops, in a side rail that appears for the active mode instead of wrap-growing the top bar into the scene
  • leftDock · rightDock — compass / readouts / camera framing, in slots that can't collide
  • statusBar — diagnostics + the live KeyLegend
  • floating — gizmo/drag readouts (still projected, but clamped into the scene rect)
  • modal — the 7 dialogs, one manager, one scrim

Z-scale (tokens, not magic numbers)

scene 0 overlay 10 // gizmos, projected readouts chrome 20 // toolbars, docks, status floating 30 // drag readouts popup 40 // loop-cut / bevel / concave modal 50 // dialogs + scrim

Every overlay declares a tier; the shell never lets two fight for the same pixel unannounced.

4.2 — Icon-first toolbars, the context rail, and space reclaimed

  • Toolbars become icon rails. Each Pressable renders an <Icon> + tooltip (the tooltip carries the action name and its live hotkey — §4.3). A worded "reframe (F)" button becomes one glyph; tier-2's 35 controls shrink to a fraction of their current width.
  • Tier-2's context ops move off the top bar. The 16 selection-gated op-clusters (extrude/loopcut/flip/glass/detach/solidify/wheel/bevel…) live in contextRail, shown only for the active mode. The top bar stops wrapping down into the 3D view.
  • The layers row is rebuilt (the §2 mock): name + meta own the row, one inline visibility toggle, the rest behind a hover/active overflow or drag-to-reorder. A part's name is finally readable at 236px — and the row is a LayerStrip change shared with the paint editor, so both improve at once (rule-of-two).

4.3 — Self-serve, rebindable hotkeys — built on what already exists

Studio currently hand-rolls two raw busOn('__keydown') listeners (lines 1056, 3866) — the exact anti-pattern the repo's editor control contract was built to kill. We don't invent a keymap; we fold Studio into the contract and add a user-editable layer.

What already exists (and we reuse): editors/controls.ts — "THE BINDINGS ARE THE TABLE (P2)": one row per action (scope · chords · name), boot-time conflict validation, legendForScope(). · useEditorControls(scope, {active, handlers}) — the one dispatcher (chord normalization + typing gate, so a focused TextInput never triggers undo). · KeyLegend.tsx — renders the live map, can't drift. · editors/workbench/settings/store.ts — the P2 registry that persists knob edits on the V20 'tuning' channel. The contract's own header says the remaining transports get folded in "by ADDING rows, not new listeners."
  1. Add a 'studio' scope to controls.ts — one row per action (undo, redo, reframe, mode.object…paint = 1–6, tool move/rotate/scale, extrude, loop-cut, delete, cancel/Esc, …). Default chords reproduce today's bindings exactly.
  2. Replace both busOn closures with useEditorControls('studio', {active, handlers}). The dispatcher already owns the typing gate, so the hand-written "TextInput eats the key" guard (req_0978) is deleted, not copied.
  3. Add a user-override layer: resolved binding = default ∘ user-override. Overrides persist through the existing settings store / 'tuning' channel under a stable key; conflicts surface as an inline warning (not a boot crash) since the user can now author them.
  4. Surface a "Hotkeys" panel in the settings door: each action lists its name + current chord + a "press a key to rebind" capture + reset-to-default. Because KeyLegend and every tooltip read the same table, the on-screen hints update the instant you rebind.

7 · Frozen vs rebuilt

Behavioral parity — HARD

  • Studio.tsx is never edited; it stays as the diff source of truth.
  • Every useHotState/localstore key byte-identical ('studio:showScale', 'studio:mirrorMask', STUDIO_PAINT_KEY, …) — a changed key silently resets state.
  • Hook-call order and effect order preserved; refs stay single, threaded through hook returns.
  • Every action does the same thing it does today; default hotkeys reproduce current bindings exactly.
  • StudioViewport's 18-field props shape unchanged.

Layout — REBUILT (on purpose)

  • Absolute boxes → dock zones; mount-order stacking → a z-token scale.
  • Worded buttons → <Icon> + tooltip (name + live hotkey).
  • Tier-2's wrapping ops → a per-mode context rail (no growth into the scene).
  • Layers row → name-first; verbs on hover/overflow/drag.
  • Hotkeys → rebindable in settings, no code change.

Verification splits accordingly: logic by identical results + self-shot; layout by you driving the live editor (the part a pixel-diff can't judge, and shouldn't).

10 · Verification protocol

  • Build green at every checkpoint — tools/rjit ship hmsc-int; never stack two steps before a build.
  • Self-shot, never desktop capture — tools/rjit shot hmsc-int --route <r> --out /tmp/studio-<step>.png, cited by path. The app reads back its own frame.
  • The matrix: empty boot · part added · object gizmo drag · face select + extrude · loop-cut popup · paint stroke · backdrop placed · a dialog open. Logic identical old↔new.
  • UI-specific checks: a layer name is readable at 236px · the top bar never grows into the scene · no overlay sits on top of another · rebind a hotkey → it persists across a reload · every tooltip shows its current chord · no instructional narration left in permanent chrome (hints moved to legend/empty-state).
  • Diff discipline: git diff --stat vs the frozen Studio.tsx shows leaf bodies arriving unchanged — large moves, near-zero logic edits. UI files are the only place real line-level change is expected.
Net result. StudioViewport drops from ~2,680 lines to a ~200-line orchestrator; the heaviest new file is a hook or a panel in the low hundreds. Editing the camera, the paint logic, or the tier-2 tools each means opening one focused file. And the viewport itself stops fighting you: tools dock instead of pile, icons reclaim the width, the layers panel shows its names, and any hotkey you dislike is one settings click from changing — no one to ask.
