# Angle 09 — Open-Source Implementations (Deep Read)

All repos below were cloned (`git clone --depth 1`) and read on 2026-07-28. Every license statement comes from the LICENSE/COPYING file or in-file header of the actual clone. File paths are repo-relative; line numbers are from the cloned HEAD and will drift.

## Claims (with confidence)

- Claim (high): For porting into a proprietary engine, the two directly usable weight-solver codebases are libigl's BBW (MPL-2.0: `include/igl/bbw.cpp`, 145 lines) and Abdrashitov's weight-inpainting transfer (MIT: `src/utils.py`, ~300 lines total). Both verified by clone and read; neither is copyleft.
- Claim (high): The Pinocchio reference library is LGPL, not MIT: `Pinocchio/COPYING` is LGPL-2.1 and `README.txt` states the library is "distributed under the GNU LGPL" while only the DemoUI is MIT. The bone-heat solve is `Pinocchio/attachment.cpp`, `AttachmentPrivate1` constructor (lines 49–193), including the literal comment `//We have -Lw+Hw=HI, same as (H-L)w=HI`.
- Claim (high): Blender's "With Automatic Weights" is `heat_bone_weighting()` at `source/blender/editors/armature/meshlaplacian.cc:624`, entered via `ED_object_vgroup_calc_from_armature()` → `add_verts_to_dgroups()` in `armature_skinning.cc`. The file carries `SPDX-License-Identifier: GPL-2.0-or-later` — reading it is fine, porting any of it into a proprietary engine is not.
- Claim (high): RigNet is dual-licensed; the operative per-file line is, verbatim: `# RigNet is made available under General Public License Version 3 (GPLv3), or under a Commercial License.` Its `LICENSE-GPLv3.txt` is the stock GNU GPL v3 text. Pretrained checkpoints and the ModelsResource-RigNetv1 dataset are Google Drive links with no separate license text anywhere in the repo.
- Claim (high): ozz-animation (MIT) contains no weight solver anywhere in `src/` — `ozz::geometry::SkinningJob` is runtime matrix-palette LBS only; weights must come from elsewhere (its samples extract them from FBX).
- Claim (high): 2TallTim's Maya Direct Delta Mush plugin has NO license file (checked whole tree + README) → default all-rights-reserved; the legally safe DDM reference is libigl's `include/igl/direct_delta_mush.cpp` (MPL-2.0) + tutorial 408.
- Claim (medium): No faithful open-source implementation of Dionne & de Lasa's geodesic voxel binding (Maya's GVB) exists; the nearest open reading material is sketchpunklabs/autoskinning (MIT, staged WebGL prototypes: voxelize → flood-fill → bone intersect → voxel distance crawl) plus RigNet's `geometric_proc/compute_volumetric_geodesic.py` (GPL).
- Claim (medium): libigl fences its TetGen wrapper into `include/igl/copyleft/tetgen/` because TetGen is aggressively copyleft (AGPL per common knowledge; libigl's own copyleft README says the subtree is "under a more aggressive copyleft than MPL2 … most notably … GPL"). A proprietary user of BBW must supply tet meshes some other way or license TetGen.
- Claim (medium): The three SSDR-family codebases (EA Dem Bones BSD-3, dalton-omens MIT Python, Mukai MIT C++) solve a different problem — weights+bones FROM an animated mesh sequence — but their per-vertex bounded/convex least-squares weight steps are the best open references for "solve weights given transforms".

## Technical detail

**Pinocchio (Baran & Popović 2007 reference code)** — https://github.com/elrond79/Pinocchio — C++, ~3.3k lines core. License: library = LGPL-2.1-or-later (`Pinocchio/COPYING`; per-file headers: "version 2.1 … or (at your option) any later version"); `DemoUI/` = MIT per `README.txt`. Read: `Pinocchio/attachment.cpp` (258 ln) — bone distances via `distsqToSeg`, visibility = raycast `tester->canSee()` AND `vectorInCone()` against vertex normal fan (line 102); heat coefficient `H[i] += initialHeatWeight / SQR(dist_closest)` (136); cotangent Laplacian assembled inline (140–158); per-bone solve through its own sparse Cholesky (`SPDMatrix`/`LLTMatrix`, `lsqSolver.cpp`, 372 ln); weights thresholded and renormalized (181–192). `embedding.cpp` (600 ln) = skeleton-embedding optimization; `discretization.cpp` (228 ln) = sphere packing/graph; `pinocchioApi.cpp` (76 ln) = whole pipeline; `AttachWeights/AttachWeights.cpp` = fork-added CLI that skips embedding and attaches weights to a given skeleton. Why read: the original bone-heat, small enough for one sitting; LGPL means link-don't-copy for proprietary use (reimplementing the published algorithm is fine).

**libigl** — https://github.com/libigl/libigl — C++ header-only (Eigen). License: MPL-2.0 (`LICENSE.MPL2` + per-file headers); everything under `include/igl/copyleft/` is explicitly fenced as GPL-family. Read: `include/igl/bbw.h` (API: `igl::bbw(V, Ele, b, bc, BBWData, W)` at bbw.h:62), `include/igl/bbw.cpp` (145 ln — builds biharmonic operator via `harmonic(V,Ele,2,Q)` at :56, per-handle QP via `active_set` with `Auu_pd=true`, or unconstrained `min_quad_with_fixed` at :77–79), `include/igl/active_set.cpp` (387 ln — the active-set QP), `include/igl/boundary_conditions.cpp` (257 ln — snaps point handles and bone edges onto tet-mesh vertices to build `b`/`bc`; this is the "how do bones become Dirichlet constraints" file), `tutorial/403_BoundedBiharmonicWeights/main.cpp` (loads a pre-tetrahedralized `hand.mesh` via `readMESH`:103 and skeleton `hand.tgf`:105; `boundary_conditions`:119 → `bbw`:126 → row-normalize → `lbs_matrix`:143). What you must bring: a tet mesh of the interior — `igl::copyleft::tetgen::tetrahedralize` and the purpose-built `copyleft/tetgen/mesh_with_skeleton.cpp` (inserts skeleton samples before tetting) exist but link TetGen (copyleft; buy a TetGen license or use another tetrahedralizer). Bonus: `include/igl/direct_delta_mush.cpp` (267 ln, DDM "variant 0", MPL2) + `tutorial/408_DirectDeltaMush`; `include/igl/heat_geodesics.cpp` (170 ln); `include/igl/mosek/bbw.*` (commercial-solver variant). Why read: the production-quality BBW you can legally port.

**Blender** — https://projects.blender.org/blender/blender (GitHub mirror blender/blender) — C++. License: GPL-2.0-or-later (`COPYING`; SPDX at `meshlaplacian.cc:3`). Read: `source/blender/editors/armature/meshlaplacian.cc` (1,803 ln) — `heat_bone_weighting()`:624 (takes `numbones`, deform groups, per-bone `root[]`/`tip[]`, selection mask); machinery: `heat_laplacian_create()`:564, `heat_set_H()`:503, `heat_source_distance()`:471, `heat_ray_source_visible()`:434 with BVH raycast (`heat_ray_tree_create()`:397, `bvh_callback`:364), cotan weights `laplacian_triangle_weights()`:161, system assembly `laplacian_system_construct_begin()`:196, weight floor `heat_limit_weight()`:610. Entry chain in `source/blender/editors/armature/armature_skinning.cc` (514 ln): `ED_object_vgroup_calc_from_armature()`:477 → `ARM_GROUPS_AUTO`:505 → `add_verts_to_dgroups()`:275 → `heat_bone_weighting` call at :437 (envelope mode lives in the same file). Second half of meshlaplacian.cc (~:852 on) is mesh-deform/MVC cage binding — different feature. Why read: twenty years of robustness patches on bone heat running directly on the render mesh (no tets, no voxels). GPL WARNING: understanding-only for proprietary work; reimplement from the paper, never translate this file.

**Robust Skin Weights Transfer via Weight Inpainting (SIGGRAPH Asia 2023)** — https://github.com/rin-23/RobustSkinWeightsTransferCode — Python (libigl python bindings + polyscope), 295 ln total. License: MIT ("Copyright (c) 2024 Rinat Abdrashitov"). Read: `src/utils.py` — `find_matches_closest_surface()`:65 (closest-point + distance/normal-angle thresholds produce the "confident" set), `inpaint()`:111 — the entire paper in ~40 lines: `L = 2*igl.cotmatrix`, Voronoi `massmatrix`, `Q = -L + L*Minv*L`, matched vertices as Dirichlet constraints, solved with `igl.min_quad_with_fixed(...)`:154; `smooth()`:158 post-relaxation near boundaries; demo driver `src/sphere_to_plane_transfer.py` (77 ln). Why read: cleanest possible "biharmonic-diffuse the missing weights" statement; trivially portable to any engine with one sparse solve; also the standard body→garment transfer.

**RigNet** — https://github.com/zhan-xu/RigNet — Python/PyTorch. License: GPLv3 OR commercial — per-file header verbatim: "RigNet is made available under General Public License Version 3 (GPLv3), or under a Commercial License."; `LICENSE-GPLv3.txt` = stock GPL v3; README: "This project is under LICENSE-GPLv3." Pretrained models: Google Drive link (README Quick start), no separate terms. Dataset ModelsResource-RigNetv1: 2,703 models (README:63), Drive links, no license file in-repo; the name signals The Models Resource (game-ripped content) provenance — treat as research-only. Read: `models/SKINNING.py` (74 ln, the skinning GNN), `quick_start.py` — `predict_skinning()`:275, `calc_geodesic_matrix()`:219; `run_skinning.py` (247 ln, training); and the classical gem `geometric_proc/compute_volumetric_geodesic.py` (173 ln — visibility-tested vertex→bone volumetric distances: `pts2line()`:22, `calc_pts2bone_visible_mat()`:52). Why read: the reference learned auto-rigger + the best open write-down of volumetric-geodesic skinning features; license makes it read-only for proprietary engines.

**ozz-animation** — https://github.com/guillaumeblanc/ozz-animation — C++. License: MIT (`LICENSE.md`, Guillaume Blanc). Honest framing: RUNTIME library only — it samples/blends animation and applies matrix-palette LBS; it does NOT compute skin weights (grep of `src/` finds no solver; its `fbx2mesh` sample tool extracts weights from FBX). Read: `include/ozz/geometry/runtime/skinning_job.h` (`influences_count`:107, `joint_matrices` span:110) and `src/geometry/runtime/skinning_job.cc` (500 ln of unrolled SoA/SIMD 1..N-influence skinning with optional normal/tangent paths). Why read: the runtime half of the feature, done right, permissively licensed.

**Dem Bones (EA SEED)** — https://github.com/electronicarts/dem-bones — C++ header-only (Eigen), 1,468 ln. License: BSD-3-Clause ("Copyright (c) 2025 Electronic Arts Inc.") plus a clause 4 restricting EA/SEED trademark display — code use is permissive. Different problem, label it: SSDR-family skinning DECOMPOSITION — computes weights AND bone transforms FROM an animated mesh sequence (turn simulations/vertex caches/scans into LBS rigs). Read: `include/DemBones/DemBones.h` (888 ln) — `compute()`:344 alternates `computeTranformations()`:237 (typo is in the source) and `computeWeights()`:276 (per-vertex sparse convex least squares with max-influence cap); `include/DemBones/ConvexLS.h` — `solve()`:65 (the constrained solver); `DemBonesExt.h` (289 ln, hierarchy/local-rotation extraction for DCC export). Why read: the production-grade decomposition codebase, and its weight step is a model constrained solve.

**SSDR — dalton-omens** — https://github.com/dalton-omens/SSDR — Python inside Maya (numpy/scipy core extracts cleanly). License: MIT (Dalton Omens 2018). Read: `SSDR.py` (270 ln) — `kabsch()`:12, `initialize()`:40 (whitened k-means over per-vertex motion → initial bones), `update_weight_map()`:99 with `scipy.optimize.lsq_linear(A, b, bounds=(0,1), method='bvls')`:130 then top-k re-solve for sparseness, `update_bone_transforms()`:153, driver `SSDR()`:214. Why read: the most readable end-to-end SSDR; read before Dem Bones.

**ssdr — Mukai Lab** — https://github.com/TomohikoMukai/ssdr — C++ (DirectXMath; Shift-JIS comments render as mojibake in UTF-8). License: MIT (Mukai Laboratory 2015). Read: `SSDR.h`:49 `SSDR::Decompose(Output&, const Input&, const Parameter&)`; `SSDR.cpp` (768 ln) block-coordinate descent; bundled `QuadProg.h/.cpp` (Goldfarb–Idnani QP for the weight step). Why read: compact C++ SSDR from a researcher in this exact field.

**Delta Mush — diseraluca** — https://github.com/diseraluca/DeltaMush — C++ Maya deformer. License: MIT (Luca Di sera 2018). Read: `DeltaMush/DeltaMush/DeltaMush.cpp` (436 ln): bind-time iterative Laplacian smoothing + per-vertex tangent-frame deltas; deform-time smooth-then-reapply-deltas; commit history is a documented optimization diary (AVX helpers `ComponentVector256d.h`). Not a weight solver — it's the cleanup pass that makes cheap auto-weights look good. Why read: readable, permissive classic delta mush to port behind your skinning stage.

**Direct Delta Mush — 2TallTim** — https://github.com/2TallTim/direct-delta-mush — C++ Maya plugin, `class directDeltaMush : public MPxSkinCluster` (`headers/direct_delta_mush.h`:26). License: NONE — no LICENSE file, no README license line → all rights reserved by default; read for understanding only, do not port code. Read: `source/direct_delta_mush.cpp` (491 ln) — `precompute()`:280 builds per-vertex Ω matrices using `igl::cotmatrix`:369; `deform()`:142 evaluates Le & Lewis 2019 DDM. Licensed alternative: libigl's `direct_delta_mush.cpp` (MPL2, above). Unreal's DeformerGraph DDM lives behind the Epic-account GitHub/EULA — not cloned or verified here.

**Surface Heat Diffuse Skinning — meshonline** — https://github.com/meshonline/Surface-Heat-Diffuse-Skinning — C++ CLI + Blender addon glue. License: MIT (Mingfen Wang 2018) — notably NOT GPL despite being a Blender-adjacent tool (the addon glue `addon/surface_heat_diffuse_skinning/__init__.py` is separate from the engine-agnostic core). Read: `src/main.cpp` (1,367 ln, one file): voxelization (`tribox.cpp`), bone-visibility raycasts (`raytri.cpp`), threaded iterative heat diffusion `diffuse_all_heats()`:293, `generate_weight_for_vertices()`:342, `export_bone_weights()`:390 (plain-text weight file). Open cousin of the author's paid "Voxel Heat Diffuse Skinning" addon. Why read: a complete, dependency-free auto-weight tool in a single readable file — the closest open thing to voxel-heat binding.

**autoskinning — SketchpunkLabs** — https://github.com/sketchpunklabs/autoskinning — JavaScript/WebGL2 (Three.js + GPGPU compute-via-textures/transform-feedback). License: MIT (Sketchpunk Labs 2023). Read `prototypes/` in order: `001_gpgpu_vox*.html` (GPU voxelization), `002_vox_fill_2.html` (interior flood fill), `003_vox_bone_intersect*.html`, `004_raycast_bones.html`, `005_voxel_crawl.html` (voxel distance crawl = volumetric geodesic propagation, the GVB idea), `006_vertex_data.html`, `007_refactor.html`. Why read: the only open geodesic-voxel-style pipeline found, staged so each concept is isolated; prototypes, not a library.

## What I'm unsure about

- Whether elrond79/Pinocchio is the best-maintained mirror — other forks exist (e.g. the same author's later account); I verified only this one. The original MIT project page was not re-checked.
- TetGen's own exact license (AGPL-3.0 is the widely known answer for ≥1.5) — I verified libigl's "GPL-family" fencing but did not clone TetGen itself. Check before relying on any tetrahedralizer choice; fTetWild (MPL-2.0) is the usual permissive substitute but was not verified here.
- RigNet's dataset/pretrained-model legal status: the repo ships only Drive links with no license text; my "research-only" characterization rests on the GPLv3-or-commercial code license plus The-Models-Resource provenance, not on an explicit dataset license.
- ssdr-mukai's comments are Shift-JIS (mojibake under UTF-8); I verified structure and entry points but not the documentation content.
- Unreal DeformerGraph DDM sample: login-gated, not cloned; Unity DDM ports found via search (PacosLelouch/MeshDeformUnity, V-Sekai/unity-mesh-deform-direct-delta-mush) were NOT cloned, so their licenses are unverified.
- Blender's linear-solver backend for the heat system (the `LinearSolver` type meshlaplacian.cc uses) lives elsewhere in the tree and was not chased in the sparse checkout.
- I found no open-source bone-glow (Wareham & Lasenby) implementation and no faithful GVB implementation; absence-of-evidence claims are limited to the searches run.
