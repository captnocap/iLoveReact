# Angle 03 — Geodesic Voxel Binding

Primary artifacts obtained and read in full: the SCA 2013 paper PDF (author copy, via Wayback capture of delasa.net) and the authors' expanded TVCG 2014 follow-up preprint (13 pp., same route). Maya docs read directly. Note: delasa.net now 301-redirects to a dead domain; the Wayback captures below are the working links.

## Claims (with confidence)

- Claim (high): The method is "Geodesic Voxel Binding for Production Character Meshes," Olivier Dionne & Martin de Lasa, Autodesk Inc., SCA 2013 (ACM SIGGRAPH/EG Symposium on Computer Animation, Anaheim, July 19–21 2013), DOI 10.1145/2485895.2485919. It is a fully automatic influence-weight generator for closed-form skinning (LBS/DQS), explicitly designed for meshes that are non-manifold, non-watertight, self-intersecting, or multi-component. Verified against the paper PDF.
- Claim (high): Pipeline = (1) voxelize the rest-pose mesh by GPU z-buffer slicing into interior/boundary/exterior voxels, (2) per bone, propagate geodesic distances from "bone voxels" through all non-exterior voxels with a Dijkstra-style queue relaxation, (3) hit-test each mesh vertex to its containing boundary voxel, (4) convert distance to weight with an analytic falloff, truncate to max influences, normalize.
- Claim (high): Solid classification does NOT use single-ray parity (which requires watertight input). It renders 6 orthographic view directions (±x, ±y, ±z), slicing the AABB plane by plane: back faces drawn white, then front faces black; a white pixel votes that voxel "internal" for that view. Votes are OR'd per axis pair, and a voxel is interior if at least 2 of the 3 axis pairs agree (majority voting, adapted from Nooruddin & Turk 2003's multi-view scheme). This voting is precisely what buys tolerance of holes, intersections, and multiple components.
- Claim (high): Boundary voxels are found separately (not by flood fill): an octree over the triangles plus Akenine-Möller triangle/box separating-axis overlap tests tags surface voxels; anything neither interior nor boundary is exterior. The seed pointer's "scan-convert then flood-fill interior" description is NOT how the paper does it — no flood fill is used.
- Claim (high): Distance propagation is Algorithm 1: per bone b_i, set all non-exterior voxel distances to ∞, set voxels intersecting the bone segment to 0 and push to a queue; pop, relax each non-exterior neighbor with dist = d(v_i) + |p_vi − p_vj| (Euclidean between voxel centers), push on improvement. It is a label-correcting BFS-like relaxation ("a form of Dijkstra's algorithm" — plain queue, no priority queue), run independently per bone and parallelized across bones/cores.
- Claim (high): On graph connectivity the seed pointer ("26-connected") is contradicted by the SCA 2013 text: they report settling on "the Euclidean norm between Manhattan voxel neighbor centers" (i.e., 6-connected face neighbors with Euclidean edge lengths, which also handles anisotropic voxels), having tried and rejected pure Manhattan distance and "the Euclidean norm to the center of all adjacent voxels" (26-connectivity) as "no significant improvement, more memory." Confusingly, the TVCG 2014 version states the reverse preference ("Euclidean norm to the center of adjacent voxels," rejecting the Manhattan-neighbor variant) — so 6-connected for the 2013 dense version, generalized adjacency in the 2014 sparse version.
- Claim (high): Weights: per vertex, d_j^i = d_voxel^i + |p_vertex − p_voxel| (the vertex-to-voxel-center term compensates grid coarseness / multiple vertices per voxel), normalized for scale (SCA: divided by bounding-box extent term D so ε ≤ d ≤ 1; TVCG: mesh pre-scaled into the unit cube). SCA falloff: ω_j^i = (1/((1−α)d + αd²))², α ∈ [0,1]; higher α = stiffer, more local bind. TVCG replaced it with ω_j^i = max(d_tol, d)^(−λ), λ = (1−α)λ_min + αλ_max, with λ_min = 5, λ_max = 30. Weights are then truncated to the user's max influences and renormalized.
- Claim (high): The design decouples distance computation (seconds) from weight computation (3–41 ms in Table 2), so α/falloff and max-influences can be retuned interactively at pose time without re-voxelizing — the paper's headline UX property, and why Maya's geomBind node keeps falloff/maxInfluences editable after binding.
- Claim (high): Why geodesic-through-volume beats Euclidean: Figure 2 in both papers shows Maya's Closest Distance / Closest in Hierarchy producing severe cross-limb artifacts (arm vs torso, leg vs leg) because they ignore mesh structure; voxel-geodesic paths must travel through occupied volume, so a thigh bone cannot reach the other leg. Maya's own Resolution doc closes the loop: when resolution is too coarse and "sections of the mesh become connected in voxel space," you get artifacts "similar to those that occur with the Closest Distance or Closest in Hierarchy methods."
- Claim (high): Production-junk tolerance was demonstrated, not just claimed: 10 of 11 test models (free internet meshes, zero cleanup) were non-watertight, with up to 660 separate mesh parts and 14,982 intersecting faces (Table 1); all bound successfully with 4 influences/vertex and gave "good default skinning weights without manual adjustment" under Maya HumanIK retargeted clips.
- Claim (high): Maya exposes (Bind Skin Options + geomBind command): Bind Method = Geodesic Voxel; Falloff 0–1, default 0.2 (1 = "more rigid bind," 0 = "smoother"); Resolution, power-of-two (geomBind default [256, true]), UI up to 1024 per Chris Evans ("highest possible"); Validate voxel state (post-validation pass, on by default, skippable, "useful diagnostic tool for more complex geometry"); Max Influences (bind options default 5; geomBind default −1 = all); docs advise starting coarse and increasing resolution as needed. Requirements stated: all joint influences must be enclosed inside the mesh volume, and front-face normals must point outwards (check via backface culling); "badly degenerate geometry" may still be problematic.
- Claim (high): geomBind (the Maya command implementing GVB on an existing skinCluster) "requires the GPU to run" and "is not available in headless/batch mode" per its command doc — a real pipeline constraint for build-farm auto-rigging.
- Claim (high): Limitations from the papers: quality is resolution-bound — at low res, A-stance limbs fuse in voxel space (Shockwave at 128³ vs 32³, "connecting disparate limbs and altering the bind"); fingers/fine features need higher res; voxelization dominates cost in the dense version (~10–18 s of the 12–20 s total at 256×256×128 on a 2011 MacBook Pro); badly degenerate meshes can mislabel interior voxels as exterior, and "if entire bones lie in mislabeled regions they will not be bound... as no path will exist"; correctness depends on face-normal orientation.
- Claim (high): The authors' direct follow-up is "Geodesic Binding for Degenerate Character Geometry Using Sparse Voxelization" (Dionne & de Lasa, IEEE TVCG, 2014, DOI 10.1109/TVCG.2014.2321563). Additions: unit-cube prenormalization; mipmap-style sparse voxelization (fine voxels only at surface and along bones, coarse blocks in deep interior) giving up to ~5× faster distance computation, all models binding < 3 s except one ~7 s at r = 256³; optional generalized-winding-number (Jacobson et al. 2013) reclassification of only low-scoring/ambiguous voxels; and a boundary-walk penalty ε_penalty > 1 multiplying edge costs into boundary voxels, biasing shortest paths through the interior to fix sharp-fold (armpit) artifacts (results use ε_penalty = 4).
- Claim (high): TVCG 2014 benchmarks vs alternatives: vs heat diffusion (Baran-Popović, libigl impl) GVB is visually indistinguishable on the watertight Beast but truncation-safe (HD spreads many tiny far weights; truncating them causes armpit artifacts); vs BBW, Armadillo took GVB 6.7 s (256³)/29.6 s (512³) against BBW's 721 s, and BBW's required tetrahedralization (TetGen) fails outright on meshes with intersecting triangles — the exact geometry GVB targets.
- Claim (medium): Whether shipping Maya implements the SCA 2013 falloff, the TVCG 2014 falloff, or the ε_penalty is undocumented — Autodesk docs describe only Falloff/Resolution/Validate semantics, not formulas. Proprietary; explicitly unverified.
- Claim (medium): Descendant/related work: RigNet (Xu et al., SIGGRAPH 2020) feeds per-vertex-per-bone "volumetric geodesic distances" (voxelized inside/outside via binvox at 88³, shortest paths through the interior, approximation algorithm in its released code) into its skinning GNN — the GVB distance concept as a learned-method feature. Third-party reimplementations: SketchPunk Labs' "Voxel Geodesic AutoSkinning (CPU)" JS walkthrough (explicitly based on this paper), and the commercial Blender add-on "Voxel Heat Diffuse Skinning" which is voxel-volumetric but diffuses heat rather than geodesic-falloff (related, not a GVB port). Unreal's Skeletal Editor (UE 5.3+) documents its own binding tools with no geodesic-voxel method.
- Claim (low): Community/wiki sources repeat that "resolutions higher than 256 might cause binding issues" in Maya; I could not find that sentence in the current Autodesk pages I fetched raw, so treat it as folklore of uncertain provenance (possibly older doc revisions).

## Technical detail

Input: rest-pose mesh M (vertices p_1..p_n), skeleton as transform hierarchy T_1..T_m; per-bone weight functions ω_j for p′ = Σ_j ω_j(p) T_j [p;1].

1. Preprocess (TVCG version): uniformly scale mesh+skeleton so the AABB fits [0,1]³. Build an octree to max resolution r over all triangles AND bone line segments (SAT box tests) → boundary-voxel and bone-voxel lists; octree reused for all later point-in-voxel lookups.
2. Voxelize (both versions): orthographic camera down each of ±x, ±y, ±z; for each slice of the volume, move the near clip plane to the slice depth (far plane fixed), render back faces white then front faces black to an offscreen buffer with no filtering; white pixel ⇒ that view votes the slice voxel internal. Per axis: v_(x,−x) = v_x OR v_(−x). Interior iff (v_(x,−x) + v_(y,−y) + v_(z,−z)) > 1. Tag boundary voxels via octree+SAT; rest = exterior. Implementation was fixed-function OpenGL + FBOs; GPU→CPU slice readback is the bottleneck — bit-packing slices into RGBA8 cut readbacks from 1536 to 48 at 256³. Optional (2014): re-classify only low-vote voxels with generalized winding numbers. Optional (2014): collapse the uniform grid into a sparse multiresolution set (coarse voxel kept interior if any child non-exterior; emit voxels at octree-leaf depth), so deep interior becomes a few fat voxels while surface+bone regions stay fine.
3. Distances (per bone, parallel across bones): d(all non-exterior) = ∞; d(bone voxels) = 0, enqueue; pop v_i, for each non-exterior neighbor v_j: dist = d(v_i) + β·|p_vi − p_vj| with β = ε_penalty(>1, e.g. 4) if v_j is a boundary voxel else 1; if it improves d(v_j), store and enqueue. Plain FIFO label-correcting relaxation; queue can grow large on low-branching models. Metric: Euclidean center-to-center (6-neighbor in SCA 2013; general adjacency in sparse 2014).
4. Weights: locate each vertex's voxel via the octree; d_j^i = d_voxel^i + |p_vertex − p_voxel| (then scale-normalize, clamp below by ε/d_tol). SCA 2013: ω = (1/((1−α)d + αd²))². TVCG 2014: ω = max(d_tol, d)^(−λ), λ = (1−α)·5 + α·30. Keep top-k influences (k = max influences), renormalize to Σω = 1. Distances are cached, so changing α/k is milliseconds — no re-voxelization.

Complexity/perf anchors: dense 256×256×128, 11 models, 4.7k–54k faces: voxelize ~10–18 s, distances 0.6–6.3 s, weights 3–41 ms (2.2 GHz i7 + Radeon HD 6750M). Sparse 256³: total < 3 s typical; sparse build 0.3–1.3 s; Beast at 512³ = 14.6 s.

## What I'm unsure about

- Maya's shipped formulas: whether Maya 2015+ uses the SCA 2013 falloff, the TVCG 2014 exponential falloff, the boundary ε_penalty, GWN correction, or the sparse structure is proprietary and undocumented. The docs describe knob semantics only. Do not assume parity with either paper when matching Maya output.
- The 6- vs 26-connectivity flip between the two papers' "distance metrics" paragraphs reads like the rejected/chosen lists were swapped in one of them; I report both verbatim readings. For a reimplementation, 6-connected + Euclidean center distances is the safe, paper-blessed 2013 choice.
- SCA 2013's normalizer D is literally "the product of bounding box extents," which is dimensionally odd for a distance; the TVCG unit-cube prescale supersedes it. Exact intent of D unresolved.
- Behavior for mesh pieces geodesically unreachable from any bone (disconnected in voxel space, gap wider than a voxel): the papers state the converse failure (bones in mislabeled regions bind nothing) and Maya guards via "joints must be enclosed," but neither source specifies vertex fallback for unreachable components (∞ distance → zero weight → normalization undefined). A reimplementer must define this (e.g., nearest-bone fallback or per-component nearest reachable voxel).
- Memory figures are never quantified in either paper (only "more memory"/"memory efficient" qualitatively); the 500 MB-class dense-grid arithmetic at 512³+ is my inference, not a citation, so I left it out of claims.
- Could not verify how "Puppeteer" (2025) and other recent neural rigging papers use GVB (OpenReview blocked by bot check); RigNet's usage is verified via its repo/paper instead.
- Chris Evans's site is offline (DreamHost placeholder); citation is to the Wayback capture. ACM DL and scispace PDFs returned 403; the author-copy PDF via Wayback is the accessible primary.
